Reading of the evidence:
  - PR #41942 ("fix(registry): evaluate defaultCacheDirectory lazily",
    commit 3e14efd6) made `defaultCacheDirectory()` lazy via `??=`.
  - But `registryDirectory` here is a class-field assignment whose
    initializer is an IIFE that runs EAGERLY at module evaluation time.
  - With PLAYWRIGHT_BROWSERS_PATH unset, the IIFE takes the `else`
    branch: `result2 = defaultRegistryDirectory()` ->
    `defaultCacheDirectory()` -> `computeDefaultCacheDirectory()` ->
    `throw new Error("Unsupported platform: android")` -- still at
    module load, before any MCP handshake.
  - With PLAYWRIGHT_BROWSERS_PATH set (either "0" or an absolute path),
    the IIFE takes an env branch and never calls
    defaultRegistryDirectory(), so the server starts fine (25 tools).
  - Matches the captured crash stack: computeDefaultCacheDirectory
    (coreBundle.js:33904) <- defaultCacheDirectory (:33907) <-
    defaultRegistryDirectory (:33910) <- registryDirectory IIFE
    (:34361) <- launchApp.ts (:35201) <- recorderApp.ts (:52297).
